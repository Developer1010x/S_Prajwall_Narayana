循環的複雑度測定 Clang プラグイン

関数ごとの制御フロー複雑度を測るコンパイラプラグイン • Aug 2026

コンパイル対象ファイル内の各関数の循環的複雑度を報告する Clang プラグインです。コンパイラ自体に読み込まれるため、テキストを再解析するのではなく、プリプロセス後のコードを実際の include パスとフラグのもとで取り扱います。制御フローグラフを構築せず AST を走査します。M = E − N + 2P は単一関数では分岐点 + 1 に帰着するからです。GCC 向けに書かれた C / C++ も解析でき、文式、省略形の条件演算子、計算型 goto、case 範囲、__attribute__ などの GNU 拡張に対応します。2024 年の学生プロジェクトが原型で、2026 年に LLVM 18 向けに再実装し、switch を case ごとではなく一つと数えていた点など四つの計測誤りを修正しました。

  • テスト 15 件、全件パス
  • LLVM 18、C および C++
C++ClangLLVMASTコンパイラ

Ansible community.general へのオープンソース貢献

マージ済みの上流バグ修正、自身のプロジェクトではありません • Aug 2026

自身のプロジェクトではなく、オープンソースへの貢献です。community.general は Ansible 最大のコミュニティコレクションで、多くの本番自動化環境が依存しています。snap モジュールは、存在しない snap を報告する代わりに IndexError で落ちていました。`snap info` はこの状態を二通りに報告します。複数問い合わせた場合は stdout に警告と戻り値 0、一つの場合は stderr にエラーと戻り値 1 です。パーサーは前者しか見ていなかったため、後者が空の結果を参照するコードに流れていました。2026 年 8 月にマージされたプルリクエスト 12570 で、両方の形式を扱うよう修正しました。

紹介

プロダクトを開発し、それを動かす基盤も自ら運用する AI エンジニアです。

インドのバンガロールにある Colligence Research の創業メンバーとして、AI エンジニアを務めています。プロダクト側では、MCP を用いたマルチエージェント・LLM パイプライン、コード生成サービス、およびそれらを支えるバックエンド API を開発しています。同時に、それが稼働するプラットフォームも担当しており、DevOps/SRE 機能を立ち上げ、現在も統括しています（CI/CD、Infrastructure as Code、監視・可観測性、インシデント対応、認証基盤）。開発と運用は一つの仕事だと考えています。エージェント基盤を作った者が、その障害対応も担うべきだからです。日本でのエンジニア職を希望しており、就労ビザのサポートが必要です。履歴書および職務経歴書は、ご依頼に応じてお送りいたします。

開発しているもの

MCP を介した ERP 自動化のためのマルチエージェント LLM パイプライン、構造化された入力仕様からデプロイ可能な Web アプリケーションを生成するコード生成サービス、そしてそれらを支えるバックエンド API です。人が逐一見張らなくても正しく進み続ける、長時間かつ多段階のエージェントワークフローを構築しています。

運用しているもの

これらのシステムが稼働するプラットフォームです。Colligence Research では DevOps/SRE の機能をゼロから立ち上げ、現在も統括しています。CI/CD、Linode 上での OpenTofu と Ansible による Infrastructure as Code、Docker、SSO と RBAC のための Zitadel、可観測性、アラート、インシデント対応の Runbook を担当しています。
